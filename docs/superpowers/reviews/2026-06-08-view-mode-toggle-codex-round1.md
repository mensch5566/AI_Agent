1. **P1: uni-mode long-tail signs are wrong under the current render shell.** The spec says uni long-tail SUM buckets will have no `display_negated` and therefore fall back to natural sign, but that is not what the code path does. The legacy dictionary builder clones `...base` into the synthetic SUM cell and does **not** clear `display_negated`, so the bucket inherits the first child’s sign flag; `StatementMatrix.displayValue()` then applies true negation to the entire summed bucket when `display_negated != null` ([useFinancialMatrix.ts](/Users/mensch5566/AI_Agent/.claude/worktrees/statement-view-pdf-faithful/app/components/financials-v2/useFinancialMatrix.ts:411), [StatementMatrix.tsx](/Users/mensch5566/AI_Agent/.claude/worktrees/statement-view-pdf-faithful/app/components/financials-v2/StatementMatrix.tsx:67)). That is a real correctness bug, not a nit. Resolution: in `buildMatrixUni`, when synthesizing a long-tail SUM row, explicitly set `display_negated: null` (and keep `xbrl_tag: null`) so uni-mode matches old natural-sign behavior.

2. **P2: “restore main’s buildMatrix verbatim” is not actually the clean path the spec claims.** The old uni builder body is already present in this worktree as the private `buildDictionaryMatrix()` used by current `RATIO` rendering ([useFinancialMatrix.ts](/Users/mensch5566/AI_Agent/.claude/worktrees/statement-view-pdf-faithful/app/components/financials-v2/useFinancialMatrix.ts:361)). So the real dependency story is: `main`’s builder does **not** need current PDF-only helpers like `rowIdOf`, `isLongTailUni`, `isDisplayEligiblePrototype`, or the derived attach map; those are not restoration traps. The real traps are semantic drift: if you paste `main` wholesale you risk clobbering current exports like `buildDerivedNonGaapRows`, and if you restore the old logic literally it will also resurrect metric-only rows such as `ebitda` / `free_cash_flow` inline in IS/CF because the old dictionary path has no `METRIC_ONLY_UNI` guard ([useFinancialMatrix.ts](/Users/mensch5566/AI_Agent/.claude/worktrees/statement-view-pdf-faithful/app/components/financials-v2/useFinancialMatrix.ts:113), [useFinancialMatrix.ts](/Users/mensch5566/AI_Agent/.claude/worktrees/statement-view-pdf-faithful/app/components/financials-v2/useFinancialMatrix.ts:324), [Viewer.tsx](/Users/mensch5566/AI_Agent/.claude/worktrees/statement-view-pdf-faithful/app/financials/[ticker]/Viewer.tsx:50)). Resolution: do not “restore from main” as a second pasted implementation; export/refactor the existing `buildDictionaryMatrix()` into `buildMatrixUni`, then consciously decide whether uni mode should still suppress metric-only rows.

3. **P2: mode-switching breaks chart selection state because consumers do care about the key scheme.** `StatementMatrix` itself is mostly row-key agnostic, but `Viewer` and `MatrixChart` are not: `selectedKeys`, `rowsWithData`, chart defaults, and `chartGroupOf(unit, key)` all treat `row.key` as a persistent chart identity ([Viewer.tsx](/Users/mensch5566/AI_Agent/.claude/worktrees/statement-view-pdf-faithful/app/financials/[ticker]/Viewer.tsx:71), [Viewer.tsx](/Users/mensch5566/AI_Agent/.claude/worktrees/statement-view-pdf-faithful/app/financials/[ticker]/Viewer.tsx:103), [MatrixChart.tsx](/Users/mensch5566/AI_Agent/.claude/worktrees/statement-view-pdf-faithful/app/components/financials-v2/MatrixChart.tsx:35)). If the user selects a PDF-only composite row like `operating_expense_long_tail|Restructuring` and then flips to uni mode, that key no longer exists; the chart silently degrades to an all-null dataset and the table loses selection highlighting. Non-GAAP spotlight is mostly safe because it keys off the current row set, but the chart/selection path is not. Resolution: on `viewMode` change, either reset `selectedKeys` to the statement preset, or prune to keys present in the new matrix; better still, keep separate `selectedKeysByMode`.

4. **P2: a single global toggle is too broad as specified; it should not present as meaningful on `RATIO` or `SEGMENT`.** `SEGMENT` bypasses `StatementMatrix` entirely and renders `SegmentDashboard`, so the toggle is meaningless there ([Viewer.tsx](/Users/mensch5566/AI_Agent/.claude/worktrees/statement-view-pdf-faithful/app/financials/[ticker]/Viewer.tsx:237)). `RATIO` is also effectively no-op today because current PDF mode already routes `RATIO` through the dictionary builder path, so “PDF vs uni” has no representational difference for ratios ([useFinancialMatrix.ts](/Users/mensch5566/AI_Agent/.claude/worktrees/statement-view-pdf-faithful/app/components/financials-v2/useFinancialMatrix.ts:238)). Resolution: scope the control to `IS`/`BS`/`CF` only, or at minimum hide/disable it on `RATIO` and `SEGMENT` with copy that makes the scope explicit.

5. **P2: the localStorage initialization is underspecified and the obvious implementation is hydration-unsafe.** In App Router, a client component can still be server-rendered; reading `localStorage` in the `useState` initializer is either a server crash (`window` undefined) or a server/client mismatch if you guard and return `'pdf'` on the server. The spec currently just says “initialized from localStorage,” which is not sufficient. Resolution: initialize deterministically to `'pdf'`, then read and apply persisted mode in `useEffect`; if you want to avoid a post-mount flash, gate the toggle/matrix swap behind a mounted flag.

Verdict: **not ready for design-gate approval as written; fix the long-tail sign bug, key-mode chart state handling, and scope/persistence semantics first.**
